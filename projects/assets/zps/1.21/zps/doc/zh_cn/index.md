# 基础

刚开始接触时，脚本终端可能会让人有些摸不着头脑，不过随着你对数据网络工作原理的了解逐渐加深，它的用法也会变得越发清晰简明。

要理解的第一个重要知识，是来自脚本终端的命令会在相连的所有串行总线上各运行一次。

也就是说，从终端发出`write_page "hello world"`后，相连的所有串行总线都会各自运行该命令一次。

![网络中的所有串行总线接收到同样的脚本输出](zps:textures/gui/manual/all_busses.png)

即便串行总线不支持所给命令（如收到`write_page`的机械臂），它们也依然会收到命令，只是不会响应。

实际上，比起思考终端送出了什么命令来说，考虑各串行总线执行了什么代码会更好。

`pos`、`block`等获取器中的值取自运行命令的串行总线。可借此筛选命令，仅让某一个串行总线执行它，例如：

![筛选总线](zps:textures/gui/manual/filtering.png)

在上方示例中，代码仍会在所有串行总线中运行，但只有最左侧的能通过条件判断，因此只有它能响应`if`后的命令。

_（注意：该例中脚本终端位于世界坐标`0 0 0`处。你终端里的坐标大概率会和它不一样。）_

再来看一个更具体的例子。有下图中的两个机械臂，需要用`take_item`让它们伸向各自的箱子。

我们使用地址写字板将两个机械臂分别标记为`@arm1`和`@arm2`，再将两个箱子分别标记为`@chest1`和`@chest2`。这一步不必要，但有这一步会让脚本写起来更容易。

![筛选总线](zps:textures/gui/manual/arm_example_step_1.png)

首先用一条极其简单（而且有错误）的脚本试试看。

_（确保将脚本终端的延迟设为16t）_

![筛选总线](zps:textures/gui/manual/arm_example_step_2.png)

运行后，实际的效果是：

![筛选总线](zps:textures/gui/manual/arm_example_step_3.png)

很明显有问题。两个机械臂伸向了同一个箱子！

这是因为两个串行总线都运行了取`@chest1`的代码，随后又都运行了取`@chest2`的代码。

我们可以用`pos`变量来筛选命令，修复这个问题：

![筛选总线](zps:textures/gui/manual/arm_example_step_4.png)

如此，即便两个机械臂运行的是同样的代码，它们也只会执行各自的命令。

现在再运行，我们会发现机械臂正常运作了！它们会各自伸向各自的箱子：

![筛选总线](zps:textures/gui/manual/arm_example_step_5.png)

理解这一点（各串行总线独立并行运行）是理解数据系统剩余部分的关键。牢记：脚本终端不会运行任何东西*，它只是在向相连的所有串行总线发出命令。

_* 在某些少见的情况下，脚本终端确实会运行一部分脚本；这些情况之后再进行介绍_
