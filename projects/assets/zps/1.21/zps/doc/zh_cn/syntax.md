# 语法

脚本终端可让你用基于行的简单脚本语言自动化方块。

每一行都是一条命令。终端收到红石信号时，它就会按序发送每一条命令。

---

## 工作原理

命令由下方的可链式使用的部件组成：

| 部件     | 用途                                       |
| -------- | ------------------------------------------ |
| `执行器` | 对模板方块执行一个动作。必然接受一个参数。 |
| `获取器` | 从世界或目标方块处读取一个值。不接受参数。 |
| `映射器` | 将当前值变换为其他值。有时会接受一个参数。 |

最简单的有效命令是带有相应参数的执行器：

```
set_redstone 15
```

其中，`set_redstone`是执行器，`15`是它的参数。

---

## 条件语句

在执行器前使用`if`或`unless`可让它进行条件判断：

```
if <条件> <执行器>
unless <条件> <执行器>
```

其中，`条件`是获取器→映射器链，最终会产出一个布尔值（`true`或`false`）。

- `if`会在条件为`true`时运行执行器
- `unless`会在条件为`false`时运行执行器

例如：

```
if redstone > 7 set_redstone 0
```

其中，`redstone > 7`是条件。若它求值为`true`，执行器`set_redstone`便会以参数`0`运行。

也即，该命令只会在收到强度为8及以上的红石信号时将红石信号设为0。

---

## 有备选项的条件语句

`else`可在条件判断未通过时指定备选项：

```
if <条件> <执行器> else <执行器>
unless <条件> <执行器> else <执行器>
```

- 对于`if`：
    - 若条件为`true`，执行第一个执行器
    - 若条件为`false`，执行第二个执行器

- 对于`unless`：
    - 若条件为`false`，执行第一个执行器
    - 若条件为`true`，执行第二个执行器

例如：

```
if redstone > 7 set_redstone 0 else set_redstone 15
```

其中，`redstone > 7`是条件。

- 若它求值为`true`，运行`set_redstone 0`
- 若它求值为`false`，运行`set_redstone 15`

该命令会在信号强度在8及以上时将红石信号设为0，否则设为15。

---

## 等待

可用`wait <周期数>`将执行延迟所给数个周期：

例如：

```
set_redstone 15
wait 2
set_redstone 0
```

`<周期数>`为从1到64的整数。提供其他数或不提供数，都会转而延迟1个周期。

`wait`的表现和执行器一样，但无法在`if`、`unless`、`else`处使用。

只要遇到该命令，就必定会执行，且会延迟后续命令的发送。

## 坐标类型

参数支持Minecraft的相对（`~`）和局部（`^`）坐标语法，会以终端位置为基准解析。

例如：

```
if pos == ~ ~1 ~ set_redstone 15
if pos == ^3 ^ ^-12 set_redstone 0
```

坐标会在发送命令时解析，不会留到执行时才解析。

---

## 地址

手工敲坐标很容易出错，同时使用多个坐标的时候尤其如此。**地址写字板**可使用方便记忆的名称保存方块位置，随后可在脚本中用`@名称`组件符引用。

**保存地址**：拿起地址写字板并

- **右击方块**将其位置保存为新地址（每个写字板最多15个）。
- **右击空气**打开用于重命名和删除已保存地址的界面。

地址名称中允许出现字母、数字、`.`、`_`。

**使用地址**：用地址写字板右击脚本终端可将写字板放在终端上。放置后，终端即可在所有坐标参数处使用写字板中保存的地址，在名称前加`@`即可：

```
take_items @input_chest
put_items @furnace
if block == minecraft:lava_cauldron use @bucket_dropoff
```

终端会在发送命令时将各个`@名称`替换为相应位置的`x y z`绝对坐标，和你原本手工敲出的一样。

> **地址仅在放有地址写字板的脚本终端中可用。**终端会用写字板解析它们，也即`@名称`组件符*不会*在命令方块、聊天栏等其他命令源中被解析——这些来源仅可使用字面坐标和`~`/`^`语法。

## value_of()

在字面量参数处使用`value_of(...)`，可在运行时求值：

例如：

```
set_redstone value_of(pos y - 50)
```

其中的表达式可为任意获取器→映射器链，只要它能返回所需类型的参数即可。

---

## 表达式别称

在脚本顶部使用`#def <名称> = <表达式>`，可为获取器→映射器链指定可重用的名称：

```
#def first_line = page_contents get_line 1

write_page value_of(first_line)
```

别称中允许出现字母、数字、`_`，开头不得为数字。

声明会从脚本顶部读取。读取声明时忽略空白行，脚本声明区会在第一个不以`#`开头的非空白行处结束。

别称中可以使用之前声明的别称：

```
#def line_1 = page_contents get_line 1
#def line_2 = page_contents get_line 2
#def combined = line_2 + "\n" + value_of(line_1)

write_page value_of(combined)
```

若出现同名别称，则后定义的覆盖先定义的；之后的声明和命令中再使用该别称，均会解析为后定义的。

别称声明体必须以获取器或之前定义的别称起始，这之后才可接上映射器。

## 变量

变量是可在脚本终端行间保持的值。可以向串行总线请求值，终端会保存它，以供之后的行对网络中的任意总线使用。

可用`#var <名称> = <字面量>`声明一个变量：

```
#var page = 1
```

- 值必须为字面量：数，`true`或`false`，字符串。获取器和映射器需使用`#def`。
- 变量的类型不固定：和字面量别称一样，它当前的值是什么类型，它就是什么类型。不符合所在位置需求的值会在该行出错，和其他命令类似。
- 名称需遵守的规则和别称的一致。变量无法重复声明，且其名称不得与别称重复：脚本中后出现的会被视作错误。

变量和别称一样可用在表达式的开头。各行在发送时会附带变量当时的值，这样所有总线使用的值就是一样的。别称中可以使用在其上方声明的变量，并会按同样方式取其值。

```
set_redstone value_of(page)
if page > 8 set_redstone 15 else set_redstone 0
```

### 向串行总线请求值

终端发出的所有命令都会在数据线缆中留存1刻，随后线缆会进入空闲状态，直至发出下一条命令为止。总线可在线缆空闲时回应：

- `request_value <值>`是执行器。执行它的总线会在线缆进入空闲状态时向线缆发送值，留存1刻。可用`if pos == ...`指定让哪一个总线回应。
- `receive_value <名称>`会将上一条命令收到的值存入在其上方声明的变量。终端能将该值暂存到下一次发出命令。和`wait`类似，该命令也只能在脚本终端中使用，且无法和`if`、`unless`、`else`配合。但和`wait`不同的是，该命令的执行不会消耗时间；它后方的行会立即执行。循环脚本每次发送间仍会至少等待2刻，无论其中有多少执行不消耗时间的行。

```
#var page = 1
if pos == @lectern request_value value_of(page_number)
receive_value page
if pos == @lamp set_redstone value_of(page)
```

`wait`和`receive_value`不会发送任何东西，因此在`request_value`和`receive_value`之间使用`wait`不会导致收到的值被丢弃。

`receive_value`会存储回应的值，无论值具体是什么。没有回应时，或有超过一个总线回应时，均不会改动变量：同一时间的两个回应相当于两个发送端，因此会相互碰撞。

变量会在循环间保留其值；编辑脚本后，以及通入红石信号后的第一次发送时，变量会重置为其声明值。
